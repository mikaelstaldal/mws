Made for everyday sites

The web apps you like, without the clutter.

Mobile Web Shell gives chosen sites a focused place on your phone. A web app manifest makes the experience richer, but any valid HTTPS site can be added.

◧

Just the app

A full-screen WebView without an address bar, tabs, or browser menus. Use Android Back to move through pages.

◎

Space of its own

Each saved app gets separate cookies and site data. Clear one app's data without clearing the others.

✧

Details discovered

Names, icons, colors, and launch addresses are suggested from the site when available, then saved locally.

▦

One tap away

Put a list of apps or a single favorite on your home screen with Android widgets.

⌁

Optional MyPass

Eligible Basic authentication and conventional login forms can use MyPass. You can always sign in manually.

◇

Secure addresses

HTTPS is required. The app warns before saving or handing off links with parameters that may contain credentials.

User guide

From URL to your home screen.

A few simple steps are all it takes to give a favorite site its own place.

01

Add a web app

Tap Add web app, enter a secure URL such as example.com, and give it a name. The app suggests details from the site; review them and tap Save. If discovery cannot reach the site, you can still save a valid URL.

02

Open and navigate

Tap the saved app in the list. Android Back returns to earlier pages, then closes the app. Pull down while the page is at the top to reload. Links to supported external apps ask for confirmation.

03

Make it yours

Long-press an app to edit its name, URL, and cookie preference. Use Reorder to arrange your list. Add a Mobile Web Shell widget from your Android launcher's widget picker for quick access.

04

Manage saved data

In the editor, choose Clear cookies and site data to sign out and remove one app's web data while keeping its entry. Choose Remove to delete the entry. Both actions require confirmation.

✳

Good to know

Mobile Web Shell is for trusted web apps. It does not download files or replace your browser. Configuration URLs can be included in Android device backup; sensitive-looking URL parameters trigger a warning before they are saved.

Get started

Build it.
Make it yours.

The project currently installs from source. There is no published APK or Play Store release.

  • Android 12 or later
  • JDK 21, Android SDK platform 36, and system Gradle
  • Android platform tools for adb
Full development instructions ↗
From source
  1. Create local.properties with sdk.dir=/path/to/Android/Sdk.
  2. Build the debug APK:
    gradle :app:assembleDebug
  3. Install on a connected device:
    adb install -r app/build/outputs/apk/debug/app-debug.apk

A little help

Questions that come up.

Why won't a site save?

The address must be a valid HTTPS URL. Plain HTTP, including localhost, is not accepted. Check the address and try again.

Why won't a saved app open?

The installed Android System WebView needs isolated profile support and must pass a compatibility check. Follow the reason and update options shown in the app.

Do I need MyPass?

No. MyPass is optional. If it is unavailable, you can still add and open apps and type credentials into a site's own login form.

What happens when I change a site's URL?

Moving to a different site asks for confirmation, signs out the old site, and clears that app's previous web data. A change within the same site keeps its web data.
